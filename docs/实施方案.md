# 晚风 Agent · 落地实施方案

> 目标读者：Cursor（执行者）。这份文档是实施契约：照工单做，别自由发挥。
> 版本：v2 · 2026-09-16
> 前提：现有 Python 项目（纯标准库、零依赖）继续用，不换框架、不引入 Node、不引入第三方依赖。
> 执行顺序：**M0 固化 → M1 工具循环 → M2 意图表达 → M3 会话压缩与维护**。除把固化提前外，后面三段的顺序和内容不要动。

---

## 1. 要解决什么

现在的晚风/早安是「拼一大段提示词 → 出一次话」：模型全程被动，我给什么它看什么。所以：

- 问「谢总是谁」，它只能把卡片念一遍；
- 问「我跟谢总最近聊了啥」，它根本做不到；
- 偏好每轮硬塞 20 条，噪声居多。

要变成：**先把记录消化成理解（M0），再给它循环和工具让它自己去查（M1），最后让它懂意图、会说人话（M2）、长聊不崩（M3）。**

## 4. 关键技术前提（已核实，别凭印象）

### 4.1 DeepSeek 的 Tool Calls（M1 用）

- OpenAI 兼容：请求带 `tools`，回复 `message.tool_calls`，结果用 `{"role": "tool", "tool_call_id": ..., "content": ...}` 回填。官方示例用的就是 `deepseek-flash`。
- **思考模式（默认开，effort 默认 high）的坑**：只要请求带了 `tools`，后续每一轮都必须把历史里的 `reasoning_content` 完整回传，否则 400。
- 思考模式不支持 `temperature` / `presence_penalty` / `frequency_penalty`（传了不生效）；`top_p` 下限 0.95。
- `strict` 模式（Beta）：`base_url` 换成 `https://api.deepseek.com/beta`，每个 function 标 `"strict": true`，所有属性必须有 `required`，`additionalProperties: false`。
- Chat Completions 不能在对话中间插入工具调用（模型自己发起的可以），但能插入 system 消息。

### 4.2 本地实测（当前库 841 MB）

| 操作 | 耗时 | 返回量 |
|---|---|---|
| 查某人的最近 8 条 | 2 ms | 约 120 字符 |
| 全文搜索一个关键词 | 16 ms | 8 条，可截断 |

结论：查询不是瓶颈，模型调用次数才是。

### 4.3 别人的做法（参考，不照搬）

- **Pi**：长期记忆是扩展不是核心；每轮前有 `transform_context` 钩子改写消息和系统提示；系统提示是具名分段（preamble/tools/rules/project_context/skills/cwd），每段可替换、可 diff；技能只放名字和描述，正文模型自己去读。
- **Pi 的压缩**：`keepRecentTokens=20000`，其余压成固定小节摘要（Goal/Constraints/Progress/Key Decisions/Next Steps/Critical Context），增量更新，先保留旧信息。
- **ChatGPT**：每轮注入预计算画像（显式记忆 + 自动提炼的密集画像 + 主题摘要 + 近期会话摘要 + 行为元数据），依赖历史时才去检索。
- **Codex**：上下文满时让模型写「交接摘要」替换原始历史，保留最近 ≤20K token 的用户消息；摘要前缀写「另一个语言模型之前做的总结」。

## 5. 数据契约（所有代码照这个写，不许改字段名）

### 5.1 固化文件 `data/people/<联系人名>.md`

```markdown
---
name: 谢总（12.22）
scene: 高中同学
oneliner: 高中那桌的主心骨，从 2023 年聊到现在没断过
stats: 41228 条（我 21108 / 对方 20120）· 2023-03 → 2026-09-12 · 每周约 229 条
model: deepseek-v4-pro
updated: 2026-09-16
confidence: high
source_hash: a1b2c3d4
stale: false
---

（150 字以内的「我眼里的他」，一段话，见 6.1 的提示词）

## 依据
- 2023-07：「孙策没用了已经」「狼太难玩了」——最早就是一起打游戏的关系
- （2–5 条，每条一句，让人能核对它有没有编）

## 历史
（旧结论，维护时挪到这里；新文件没有这一节）
```

字段含义：
- `oneliner`：人物索引用的那一句（≤40 字，从正文概括）。
- `stats`：互动统计，人类可读。
- `source_hash`：素材文本的 SHA1。素材变了 hash 就变，用于判断要不要重跑。
- `stale`：`true` 表示素材已变，待重跑。
- `confidence`：`high` / `low`（素材不足时 low）。

### 5.2 工具返回的通用规则

只查本机库；返回瘦（≤8 条、每条截 60 字、总量 ≤600 字）；过 `textutil.redact`；查不到回 `{"found": false, "reason": "..."}`，不许编。

## 6. 详细设计

### 6.1 固化（M0）

把原始记录加工成「理解」，存 `data/people/`。这是离线批处理，不依赖工具。

**取素材** `kb.sample_person(conn, name)`：

- 过滤纯占位符（`[表情]` `[图片]` `[分享/文件/链接]` `[语音]` `[文本]` `[视频]` `[位置]` `[系统消息]`）和长度 ≤1 的消息。
- 抽 7 个均匀分布的时间窗口，每窗 10 条连续消息，再加最近 26 条。
- 每行截 70 字，过 `textutil.redact`。
- 结果：`{"stats": "...", "lines": [...]}`。实测一人约 104 行、1.1KB。
- 素材不足 40 条的会话：只写 front-matter，`confidence: low`，正文写「记录太少，暂不做判断」。
- `source_hash = sha1(素材全文)`。

**固化提示词**（原样抄进代码）：

```
你在帮一个人整理「我眼里的某个人」：把原始聊天记录消化成他本人视角的一段理解，供他以后的 AI 分身引用。

硬要求：
1. 第一人称是资料主人本人，不是助手。
2. 只依据材料，不许编；材料看不出的不要写，材料不足就明说。
3. 给判断，不要罗列；数字只有在它本身说明问题时才提。
4. 不许出现字段名（关系/话题/状态），不许照抄原话，不许列群名清单。
5. 不许写"关系很好"这种空话——说清楚好在哪、在什么场景下会找他。
6. 150 字以内，一段话，不要小标题。
```

用户消息：

```
【这个人】<联系人名>（括号里是微信备注的日期，不是生日）
【素材统计】<stats>
【我和他的聊天片段（按时间，我发的标"我"，他发的标"对方"）】
<lines>

按上面的要求，写出我眼里的<名字>。
```

**批处理** `cli.py consolidate`：

- `--sample 谢总（12.22） 空想号MEK(小胖) 宝宝（9.8）`：只跑 3 个人，人工审格式和深度。
- `--top 89`：跑近圈 89 人；并发 4；断点续跑（文件在且 `source_hash` 相同就跳过）。
- 失败重试 2 次，仍失败记进 `data/people/_failures.json`，不影响其他人。
- `--model deepseek-v4-pro`：质量优先时全量用强档；默认 flash 全量、近圈前 20 人用 v4-pro 复核。
- `--check`：`stale=true` 的、或 `source_hash` 变了的，列出；`--stale` 只重跑这些。

**人物索引** `kb.person_index()`：读全部文件的 front-matter，返回 `name → oneliner`。常驻提示词，一行一人。近圈 89 人约 89 行，放得下；以后多了再分层。

### 6.2 分层（M1 起生效）

```
① 稳定段（每轮一样，可缓存）
   人设卡 → 说话方式档 → 人物索引 → 行为准则
② 按需段（这轮涉及的人才进）
   人物理解（who_is 读 data/people/*.md）+ 相关事实/偏好
③ 工具（模型自己决定要不要用）
   who_is / recent_with / search_chats / my_facts
④ 循环：模型 →（要工具就执行 → 结果回填）→ 模型，最多 2 轮工具
⑤ 会话：最近 N 轮原文 + 更早的压缩摘要
```

### 6.3 工具集（M1，只读 4 个）

工具描述写清「什么时候用」。四个都带 `strict: true`（走 `/beta`）。

**who_is(name)**：
```json
{"type":"function","function":{"name":"who_is","strict":true,
 "description":"查某个人是谁、跟我的关系、我平时怎么称呼他。问某人是谁、跟某人什么关系时用。",
 "parameters":{"type":"object","properties":{"name":{"type":"string"}},
  "required":["name"],"additionalProperties":false}}}
```
实现：优先读 `data/people/<名>.md` 的正文和 front-matter；没有文件就回退薄卡 + 互动统计。返回 `{found, name, scene, oneliner, understanding, stats}`。

**recent_with(name, limit=8)**：
```json
{"name":"recent_with","strict":true,"description":"查我跟某个人最近几轮聊天。被问到最近跟他聊了什么、他最近说了什么时用。",
 "parameters":{"type":"object","properties":{"name":{"type":"string"},"limit":{"type":"integer"}},
  "required":["name"],"additionalProperties":false}}
```
返回 `[{who:"我"|"他", text, time}]`，每条截 60 字。

**search_chats(keyword, contact="", limit=8)**：
```json
{"name":"search_chats","strict":true,"description":"在我的聊天记录里搜关键词，看我跟谁聊过、聊了什么。被问到某件事、某个话题时用。",
 "parameters":{"type":"object","properties":{"keyword":{"type":"string"},"contact":{"type":"string"},"limit":{"type":"integer"}},
  "required":["keyword"],"additionalProperties":false}}
```

**my_facts(topic="")**：
```json
{"name":"my_facts","strict":true,"description":"查关于我本人的事实和偏好（学校、实习、作息、喜好）。被问到我的情况或偏好时用。",
 "parameters":{"type":"object","properties":{"topic":{"type":"string"}},
  "required":[],"additionalProperties":false}}
```

### 6.4 循环（M1）

```python
def reply_with_tools(llm, conn, message, *, mode, partner, history, max_hops=2):
    messages = build_messages(...)
    hops, trace = 0, []
    while True:
        out = llm.chat(messages, task="agent", temperature=0.8,
                       tools=TOOLS, tool_choice="auto", thinking=False)
        if not out.tool_calls or hops >= max_hops:
            return out.text, trace
        for call in out.tool_calls:
            result = run_tool(conn, call, mode=mode)
            trace.append({"tool": call.name, "args": call.args})
            messages.append(out.as_message())
            messages.append({"role": "tool", "tool_call_id": call.id,
                             "content": json.dumps(result, ensure_ascii=False)})
        hops += 1
        if hops >= max_hops:
            messages.append({"role": "system",
                             "content": "已经查够了，现在用你查到的东西回答，不要再调用工具。"})
```

硬约束：`max_hops=2`；单轮超时 60s；任一调用失败退化成不带工具的单次回答并记日志；空内容重试最多 3 次；思考默认关（`HA_AGENT_THINKING=0`），打开就必须每轮回传 `reasoning_content`；会话累计花费超 $0.05 自动降级。

### 6.5 提示词装配（M2）

按「稳定 → 变化」拼，稳定段在前吃缓存：

```
[身份]     人设卡
[说话方式] style_profile.json 对应档位 + 原话样例
[人物索引] 一人一行（来自 oneliner）
[准则]     怎么讲人 / 不确定怎么说 / 什么时候反问 / 工具用不用
[按需]     这轮涉及的人的理解 + 相关事实/偏好
[这轮]     他是谁 + 他说的话
```

`[人物索引]` 只放一句，细节留给 `who_is` 和 `data/people/*.md`。

### 6.6 意图层（M2）

不新增组件，靠准则 + 允许的动作：

- 问「某人是谁 / 我跟某人什么关系」：一句判断 + 一两个具体细节；可以像人一样反问「你找他吗」。
- 问「最近聊了啥 / 聊过某事没」：先调工具再答。
- 闲聊（在吗 / 嗯 / 哈哈）：短句直回，不调工具。
- 求办事 / 要约：晚风按档位回；不认识的人不擅自承诺。

写死一条：**回复里不许暴露工具名和查询过程**；网页可以显示「查了：跟谢总的最近记录」一行。

### 6.7 会话与压缩（M3）

- 最近 6 轮原文照带。
- 更早的压成固定小节摘要：Goal / Constraints & Preferences / Progress / Key Decisions / Next Steps / Critical Context，增量更新（先保留旧信息）。
- 摘要作为一条 system 消息注入，前缀写明「这是之前的对话摘要」。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| DeepSeek 工具调用偶发不稳（历史上有循环调用、空回复） | 步数上限 2；空内容重试；strict 模式；失败降级单次回答；日志可追 |
| 思考模式 + tools 的 reasoning_content 回传坑 | 默认关思考；打开时按文档回传并写单测 |
| 固化时模型编造 | 提示词要求「只依据材料」；`## 依据` 保留引用供人工核对；样本先审再全量 |
| 素材不足的人 | confidence=low，正文明说记录太少，只进索引 |
| 工具被滥用 | 描述写清「什么时候用」；准则「闲聊别查」；--trace 观察 |
| 工具返回太长 | 硬上限 8 条 × 60 字、总量 600 字 |
| 隐私 | 只查本机库；发给模型的只有摘要片段；过 redact |
| 成本失控 | 会话预算闸 $0.05；cost 命令随时看 |
| 改坏现有功能 | --no-tools 回退；先跑 20 轮回归 |

## 11. 不做的事（边界）

- 不自动发微信、不接非官方通道。
- 不做写入型工具（M0–M3 全只读）。
- 不接设备控制、日历、待办（行动层另开一版）。
- 不引入 Node / Pi / Cursor SDK；循环和工具自己写，保持零依赖。
- 不写死任何回复话术。
